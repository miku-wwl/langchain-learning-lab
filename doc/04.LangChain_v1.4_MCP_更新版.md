# 04. LangChain v1.4 接入 MCP（更新版）

> 基线：LangChain 1.4.2 / Python >= 3.10 / MCP 2026-07-28 / Local-first
>
> 本章更新目标：保留原课程“体验 MCP → 理解协议 → STDIO / Streamable HTTP → Agent 接入 MCP → 自己写 MCP Server”的主线，更新到当前 MCP Python SDK v2 与 LangChain v1.4 的一方 MCP 集成。

## 课程目标

- 理解 MCP 的 Host / Client / Server 三层关系。
- 理解 MCP 与 LLM Tool Calling 的关系：MCP 不等于 Function Calling，也不替代 Agent Runtime。
- 理解 MCP Server 可以暴露 Tools、Resources、Prompts；本章重点仍放在 Tools。
- 理解当前标准传输：STDIO 与 Streamable HTTP。
- 使用官方 MCP Python SDK v2 构建本地 MCP Server。
- 使用原生 MCP Client 完成 Tool Discovery 与 Tool Call。
- 使用 LangChain v1.4 的 `langchain.mcp.MCPAdapter` 把 MCP Tools 交给 `create_agent()`。
- 认识 MCP 的安全边界：本地子进程、远程服务、凭证、权限与 Human Approval。

## 0. 这次更新最重要的变化

| 原 PDF 的写法 / 理解 | 2026 更新后的建议 |
|---|---|
| 主要使用 `langchain-mcp-adapters` | LangChain 1.4 已提供一方 `langchain.mcp` + `MCPAdapter`；旧适配器仓库已归档，新教程优先使用一方 API |
| MCP 本质上只是统一 Function Call | MCP 是 AI 应用与外部系统之间的开放协议，可暴露 Tools、Resources、Prompts 等；Tool Calling 只是本章最重要的使用场景 |
| Python Server 使用 `FastMCP` | 官方 MCP Python SDK v2 已将高层类改名为 `MCPServer` |
| Streamable HTTP 被描述成长连接 | 当前 2026-07-28 规范是“每条客户端消息一个 HTTP POST”；服务端可返回 JSON 或该请求范围内的 SSE 流 |
| SSE 与 Streamable HTTP 并列使用 | 新实现优先 STDIO / Streamable HTTP；旧 SSE 只用于兼容旧服务 |
| STDIO 只是“在本地执行程序” | 更准确：Client 启动 Server 子进程，通过 stdin/stdout 交换 JSON-RPC；stdout 只能输出合法 MCP 消息，日志写 stderr |
| MCP 接入主要依赖第三方客户端 UI | 本章改成 100% Local-first：先写 MCP Server/Client，再接 LangChain Agent；Cline/VS Code 等 Host 只作为可选体验 |
