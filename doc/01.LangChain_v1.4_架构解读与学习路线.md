# 一、新版 LangChain v1.4 架构解读与学习路线梳理

> 基于原《新版LangChain架构解读与学习路线梳理》更新。  
> **版本基线：LangChain 1.4.x；本文按 1.4.2 编写（2026-09-23 核验）。**  
> Python 要求：**Python >= 3.10，< 4.0**。

AI 大模型技术发展很快，与大模型同步发展的，是 Agent。通过 Agent，我们可以把模型、工具、状态、业务规则和外部系统组织到一起，构建真正可执行的智能应用。

LangChain 依然是最有影响力的 Agent 开发框架之一。不过到了 v1.4，理解它时最好不要再把它简单看成“一个 Chain 库”，而要把它理解成一套 **Agent + Harness + Orchestration + Observability** 的开发生态。

## 课程目标

- 理解 LangChain v1.4 的生态体系
- 搭建基础 Python 开发环境
- 访问不同大模型
- 给模型绑定 Tools
- 用 `create_agent` 构建第一个 Agent
- 理解短期记忆 / Checkpointer
- 了解 v1.4 新增的原生 MCP 适配能力
- 用 LangSmith 做 tracing、debug 与 evaluation

# 一、LangChain、LangGraph、Deep Agents、LangSmith 到底是什么？

LangChain 官网：<https://docs.langchain.com/>

在 v1.4 的官方定位里，这几个组件的关系比旧版描述更清晰：

- **Deep Agents**：偏“开箱即用”的高阶 Agent。已经组合了规划、上下文压缩、文件系统、子 Agent 等能力，适合希望快速获得完整 Agent 能力的场景。
- **LangChain**：提供 `create_agent`，可以把它理解成一个高度可配置的 **Agent Harness**。你负责选择 Model、Tools、Prompt、Middleware 等组件，再由框架组织 Agent Loop。
- **LangGraph**：底层的低级编排框架和运行时。适合需要显式状态图、确定性流程 + Agent 混合流程、持久化、恢复、HITL 等高级控制的场景。
- **LangSmith**：工程平台，负责 tracing、debug、evaluation、datasets、monitoring 等生产化能力。

一个很重要的理解是：

> **Agent = Model + Harness**

Model 负责“思考和选择下一步”，Harness 负责模型周围的一切：Prompt、Tools、Middleware、状态、持久化、错误处理、人工介入等。

LangChain 的 `create_agent` 底层建立在 LangGraph 之上，所以普通 Agent 开发可以先学 LangChain；当你需要更复杂的状态机、分支、恢复与编排时，再下沉到 LangGraph。

## v1.3 -> v1.4 最值得关注的变化

LangChain 1.4 并不是一次大规模破坏性升级，1.x 仍保持兼容性思路。对学习者来说最明显的新能力是：

1. **新增第一方 `langchain.mcp` 命名空间**。
2. 提供 **`MCPAdapter`**，可以把 MCP Server 的工具直接转换成 LangChain Tools，再交给 `create_agent`。
3. MCP 能力基于 FastMCP，支持 HTTP、stdio、本地进程、in-process server、多 server config 等连接方式。
4. `langchain.mcp` 当前仍标记为 **beta**，使用时应固定版本并关注后续 API 调整。

# 二、快速体验 LangChain v1.4

## 1、安装依赖

LangChain Python v1.4.2 要求 Python 3.10+。建议直接使用 Python 3.11 / 3.12 / 3.13。

```bash
# 核心包
pip install -U "langchain==1.4.2" langgraph

# OpenAI / OpenAI-compatible 模型支持
pip install -U langchain-openai

# 如果要使用通义千问原生社区集成
pip install -U langchain-community dashscope

# v1.4 原生 MCP 支持（会引入 FastMCP）
pip install -U "langchain[mcp]==1.4.2"
```

> 如果你只是在学习，不一定要把所有 provider 一次装完。实际项目更推荐“用到哪个 provider，再安装哪个 integration”。

### LangSmith 环境变量（可选）

```python
import os
from config.load_key import load_key

os.environ["LANGSMITH_TRACING"] = "true"
os.environ["LANGSMITH_PROJECT"] = "firstLangChainDemo"
os.environ["LANGSMITH_API_KEY"] = load_key("LANGSMITH_API_KEY")
```

## 2、访问大模型

LangChain 的价值之一，是提供统一的模型接口。应用可以在相对少改代码的情况下切换 provider。

下面继续使用原教程里的通义千问 OpenAI-compatible API：

```python
from config.load_key import load_key
from langchain.chat_models import init_chat_model

model = init_chat_model(
    "qwen-plus",
    model_provider="openai",
    api_key=load_key("DASHSCOPE_API_KEY"),
    base_url="https://dashscope.aliyuncs.com/compatible-mode/v1",
)

response = model.invoke("你是谁？")
print(response.content)
```

也可以继续使用社区包中的 `ChatTongyi`：

```python
from config.load_key import load_key
from langchain_community.chat_models import ChatTongyi

llm = ChatTongyi(
    model="qwen-plus",
    api_key=load_key("DASHSCOPE_API_KEY"),
)

print(llm.invoke("你是什么模型？").content)
```

学习时更重要的不是记住某个 provider 的类名，而是理解：

> **Model 是 Agent 的推理核心，但 LangChain 希望把具体模型供应商隔离在统一接口之后。**

## 3、给大模型增加 Tools

如果模型只能生成文本，它只是 Chat Model。给模型提供 Tools 后，它才开始具备“调用外部能力”的基础。

```python
import datetime

from config.load_key import load_key
from langchain_openai import ChatOpenAI
from langchain.tools import tool

llm = ChatOpenAI(
    model="qwen-plus",
    base_url="https://dashscope.aliyuncs.com/compatible-mode/v1",
    api_key=load_key("DASHSCOPE_API_KEY"),
)

@tool
def get_current_date() -> str:
    """获取今天日期。"""
    return datetime.datetime.today().strftime("%Y-%m-%d")

llm_with_tools = llm.bind_tools([get_current_date])

messages = [
    {"role": "user", "content": "今天是几月几号？"}
]

# 第一次调用：模型判断是否需要调用工具
ai_msg = llm_with_tools.invoke(messages)
messages.append(ai_msg)

# 手动执行工具调用
all_tools = {"get_current_date": get_current_date}

for tool_call in ai_msg.tool_calls:
    selected_tool = all_tools[tool_call["name"]]
    tool_msg = selected_tool.invoke(tool_call)
    messages.append(tool_msg)

# 第二次调用：模型基于工具结果生成最终回答
final_msg = llm_with_tools.invoke(messages)
print(final_msg.content)
```

这个例子非常重要，因为它把 **Agent Loop 的底层机制** 暴露出来了：

```text
User
  -> Model
      -> 是否需要 Tool？
          -> Tool Call
              -> Tool Result
                  -> Model
                      -> Final Answer
```

你之后使用 `create_agent`，本质上就是把这套循环交给框架管理。
