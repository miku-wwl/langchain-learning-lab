# 一、新版 LangChain v1.4 架构解读与学习路线梳理

> 基于原《新版LangChain架构解读与学习路线梳理》更新。  
> **版本基线：LangChain 1.4.x；本文按 1.4.2 编写（2026-09-23 核验）。**  
> Python 要求：**Python >= 3.10，< 4.0**。

AI 大模型技术发展很快，与大模型同步发展的，是 Agent。通过 Agent，我们可以把模型、工具、状态、业务规则和外部系统组织到一起，构建真正可执行的智能应用。

LangChain 依然是最有影响力的 Agent 开发框架之一。不过到了 v1.4，理解它时最好不要再把它简单看成“一个 Chain 库”，而要把它理解成一套 **Agent + Harness + Orchestration + Observability** 的开发生态。

## 课程目标

- 理解 LangChain v1.4 的生态体系
- 搭建基础 Python 开发环境
- 访问不同大模型
- 给模型绑定 Tools
- 用 `create_agent` 构建第一个 Agent
- 理解短期记忆 / Checkpointer
- 了解 v1.4 新增的原生 MCP 适配能力
- 用 LangSmith 做 tracing、debug 与 evaluation

# 一、LangChain、LangGraph、Deep Agents、LangSmith 到底是什么？

LangChain 官网：<https://docs.langchain.com/>

在 v1.4 的官方定位里，这几个组件的关系比旧版描述更清晰：

- **Deep Agents**：偏“开箱即用”的高阶 Agent。已经组合了规划、上下文压缩、文件系统、子 Agent 等能力，适合希望快速获得完整 Agent 能力的场景。
- **LangChain**：提供 `create_agent`，可以把它理解成一个高度可配置的 **Agent Harness**。你负责选择 Model、Tools、Prompt、Middleware 等组件，再由框架组织 Agent Loop。
- **LangGraph**：底层的低级编排框架和运行时。适合需要显式状态图、确定性流程 + Agent 混合流程、持久化、恢复、HITL 等高级控制的场景。
- **LangSmith**：工程平台，负责 tracing、debug、evaluation、datasets、monitoring 等生产化能力。

一个很重要的理解是：

> **Agent = Model + Harness**

Model 负责“思考和选择下一步”，Harness 负责模型周围的一切：Prompt、Tools、Middleware、状态、持久化、错误处理、人工介入等。

LangChain 的 `create_agent` 底层建立在 LangGraph 之上，所以普通 Agent 开发可以先学 LangChain；当你需要更复杂的状态机、分支、恢复与编排时，再下沉到 LangGraph。

## v1.3 -> v1.4 最值得关注的变化

LangChain 1.4 并不是一次大规模破坏性升级，1.x 仍保持兼容性思路。对学习者来说最明显的新能力是：

1. **新增第一方 `langchain.mcp` 命名空间**。
2. 提供 **`MCPAdapter`**，可以把 MCP Server 的工具直接转换成 LangChain Tools，再交给 `create_agent`。
3. MCP 能力基于 FastMCP，支持 HTTP、stdio、本地进程、in-process server、多 server config 等连接方式。
4. `langchain.mcp` 当前仍标记为 **beta**，使用时应固定版本并关注后续 API 调整。

# 二、快速体验 LangChain v1.4

## 1、安装依赖

LangChain Python v1.4.2 要求 Python 3.10+。建议直接使用 Python 3.11 / 3.12 / 3.13。

```bash
# 核心包
pip install -U "langchain==1.4.2" langgraph

# OpenAI / OpenAI-compatible 模型支持
pip install -U langchain-openai

# 如果要使用通义千问原生社区集成
pip install -U langchain-community dashscope

# v1.4 原生 MCP 支持（会引入 FastMCP）
pip install -U "langchain[mcp]==1.4.2"
```

> 如果你只是在学习，不一定要把所有 provider 一次装完。实际项目更推荐“用到哪个 provider，再安装哪个 integration”。

### LangSmith 环境变量（可选）

```python
import os
from config.load_key import load_key

os.environ["LANGSMITH_TRACING"] = "true"
os.environ["LANGSMITH_PROJECT"] = "firstLangChainDemo"
os.environ["LANGSMITH_API_KEY"] = load_key("LANGSMITH_API_KEY")
```

## 2、访问大模型

LangChain 的价值之一，是提供统一的模型接口。应用可以在相对少改代码的情况下切换 provider。

下面继续使用原教程里的通义千问 OpenAI-compatible API：

```python
from config.load_key import load_key
from langchain.chat_models import init_chat_model

model = init_chat_model(
    "qwen-plus",
    model_provider="openai",
    api_key=load_key("DASHSCOPE_API_KEY"),
    base_url="https://dashscope.aliyuncs.com/compatible-mode/v1",
)

response = model.invoke("你是谁？")
print(response.content)
```

也可以继续使用社区包中的 `ChatTongyi`：

```python
from config.load_key import load_key
from langchain_community.chat_models import ChatTongyi

llm = ChatTongyi(
    model="qwen-plus",
    api_key=load_key("DASHSCOPE_API_KEY"),
)

print(llm.invoke("你是什么模型？").content)
```

学习时更重要的不是记住某个 provider 的类名，而是理解：

> **Model 是 Agent 的推理核心，但 LangChain 希望把具体模型供应商隔离在统一接口之后。**

## 3、给大模型增加 Tools

如果模型只能生成文本，它只是 Chat Model。给模型提供 Tools 后，它才开始具备“调用外部能力”的基础。

```python
import datetime

from config.load_key import load_key
from langchain_openai import ChatOpenAI
from langchain.tools import tool

llm = ChatOpenAI(
    model="qwen-plus",
    base_url="https://dashscope.aliyuncs.com/compatible-mode/v1",
    api_key=load_key("DASHSCOPE_API_KEY"),
)

@tool
def get_current_date() -> str:
    """获取今天日期。"""
    return datetime.datetime.today().strftime("%Y-%m-%d")

llm_with_tools = llm.bind_tools([get_current_date])

messages = [
    {"role": "user", "content": "今天是几月几号？"}
]

# 第一次调用：模型判断是否需要调用工具
ai_msg = llm_with_tools.invoke(messages)
messages.append(ai_msg)

# 手动执行工具调用
all_tools = {"get_current_date": get_current_date}

for tool_call in ai_msg.tool_calls:
    selected_tool = all_tools[tool_call["name"]]
    tool_msg = selected_tool.invoke(tool_call)
    messages.append(tool_msg)

# 第二次调用：模型基于工具结果生成最终回答
final_msg = llm_with_tools.invoke(messages)
print(final_msg.content)
```

这个例子非常重要，因为它把 **Agent Loop 的底层机制** 暴露出来了：

```text
User
  -> Model
      -> 是否需要 Tool？
          -> Tool Call
              -> Tool Result
                  -> Model
                      -> Final Answer
```

你之后使用 `create_agent`，本质上就是把这套循环交给框架管理。

---

## 4、封装成 Agent：`create_agent`

v1.4 官方仍然推荐从 `create_agent` 开始构建普通 Agent。

```python
from langchain.agents import create_agent

agent = create_agent(
    model=llm,
    tools=[get_current_date],
    system_prompt="You are a helpful assistant.",
)

result = agent.invoke({
    "messages": [
        {"role": "user", "content": "今天是几月几号？"}
    ]
})

print(result["messages"][-1].content)
```

此时 Tool Loop、消息传递、状态流转都由 Agent Harness 负责。

在简单项目里，你通常优先使用 `create_agent`；只有当控制流复杂到需要显式 Graph 时，再直接写 LangGraph。

---

## 5、提示词模板

复杂 Agent 除了 Model 和 Tools，Prompt 仍然非常关键。

```python
from langchain_core.prompts import ChatPromptTemplate

prompt_template = ChatPromptTemplate.from_messages([
    ("system", "Translate the following from English into {language}"),
    ("user", "{text}"),
])

prompt = prompt_template.invoke({
    "language": "Chinese",
    "text": "Hello, how are you?",
})

print(prompt)
```

但是到了 Agent 场景，需要建立一个更现代的认识：

- 静态规则可以放在 `system_prompt`
- 动态上下文可以来自 State / Context
- 更复杂的运行时行为可以通过 Middleware 注入

也就是说，Prompt 依然重要，但 **Harness 不再只是 Prompt + Tool 的简单拼接**。

## 6、构建短期记忆

LangChain 的短期记忆，本质上是 **thread-level state persistence**。

最常见的做法是给 Agent 配置 `checkpointer`：

```python
from langchain.agents import create_agent
from langgraph.checkpoint.memory import InMemorySaver

saver = InMemorySaver()

agent = create_agent(
    model=llm,
    tools=[get_current_date],
    system_prompt="You are a helpful assistant.",
    checkpointer=saver,
)

thread_config = {
    "configurable": {
        "thread_id": "1"
    }
}

response = agent.invoke(
    {
        "messages": [
            {"role": "user", "content": "今天是几月几号？"}
        ]
    },
    thread_config,
)["messages"][-1].content

print("1>>", response)

response = agent.invoke(
    {
        "messages": [
            {"role": "user", "content": "那明天呢？"}
        ]
    },
    thread_config,
)["messages"][-1].content

print("2>>", response)
```

这里的关键不是 `InMemorySaver` 本身，而是理解：

```text
thread_id
   -> 对应一个会话线程
      -> Agent State
         -> messages / 自定义状态
            -> Checkpointer 持久化
```

`InMemorySaver` 只适合本地学习和测试。生产环境通常要换成数据库支持的 checkpointer，才能跨进程、跨重启恢复。

如果需要跨不同 thread / session 保存用户级信息，则属于 **Long-term Memory**，不要和 Checkpointer 混为一谈。

# 三、v1.4 新能力：原生 MCPAdapter

这是从 v1.3 学习资料升级到 v1.4 时最值得补上的内容。

MCP（Model Context Protocol）的目标，是把“工具与上下文如何提供给模型”标准化。

在 v1.4 之前，LangChain 生态里已经有 MCP adapter；到了 v1.4，LangChain 增加了第一方 `langchain.mcp` 命名空间和 `MCPAdapter`。

## 安装

```bash
pip install -U "langchain[mcp]==1.4.2"
```

## 最小示例

```python
from langchain.agents import create_agent
from langchain.mcp import MCPAdapter

async def main():
    async with MCPAdapter("https://example.com/mcp") as adapter:
        tools = await adapter.list_tools()

        agent = create_agent(
            model="openai:gpt-5.5",
            tools=tools,
        )

        result = await agent.ainvoke({
            "messages": [
                {"role": "user", "content": "帮我查询相关信息"}
            ]
        })

        return result
```

你可以把这段关系理解成：

```text
MCP Server
   -> MCPAdapter.list_tools()
      -> LangChain Tools
         -> create_agent(...)
            -> Agent Loop
```

因此，MCP 的意义不是“替代 Agent”，而是降低 Agent 与外部工具系统之间的耦合。

### v1.4 MCP 学习时要注意

- `langchain.mcp` 要求 LangChain >= 1.4.0
- 当前仍为 beta
- 底层基于 FastMCP
- 支持远程 HTTP、stdio、本地脚本、in-process server、多 Server 配置等形式
- 如果你正在学 MCP，建议优先学这一套第一方接口，而不是继续把旧的第三方 adapter 当成主路线

# 四、LangSmith：Tracing、Debug、Evaluation

如果你设置了：

```python
os.environ["LANGSMITH_TRACING"] = "true"
os.environ["LANGSMITH_PROJECT"] = "firstLangChainDemo"
os.environ["LANGSMITH_API_KEY"] = load_key("LANGSMITH_API_KEY")
```

那么 Agent 的模型调用、工具调用和执行链路可以进入 LangSmith 进行追踪。

LangSmith 的价值远不只是“看日志”。一个成熟 Agent 应用通常需要：

- Trace：看模型和 Tool 到底执行了什么
- Debug：定位错误发生在哪一步
- Dataset：沉淀真实测试样本
- Evaluation：判断回答质量、工具选择、任务完成情况
- Regression：改 Prompt / Model / Tool 后验证有没有退化
- Monitoring：上线后持续观察行为

你可以把 Agent 工程化过程理解成：

```text
先让它能跑
  -> 再让它可观察
     -> 再建立 Eval
        -> 再做优化
           -> 最后才谈稳定生产
```

这也是为什么学习 LangChain 时，不能只停留在“会调模型 + 会绑定工具”。

# 五、v1.4 核心组件总结

到这里，你已经接触到构建 Agent 最重要的一批基础组件：

| 组件 | 作用 |
|---|---|
| Model | 与大模型交互，完成推理与下一步决策 |
| Tools | 给模型增加外部执行能力 |
| Prompt | 给模型提供任务规则和上下文 |
| Agent / Harness | 组织 Model + Tools + Prompt + Middleware 的循环 |
| State | 保存当前 Agent 执行上下文 |
| Checkpointer | 保存 thread-level 短期状态，支持恢复 |
| Middleware | 在 Agent Loop 周围插入动态行为、控制与策略 |
| MCPAdapter | 把 MCP Server 的能力适配为 LangChain Tools |
| LangGraph | 负责更低层、更可控的状态图与工作流编排 |
| LangSmith | tracing、debug、evaluation 与生产观测 |

所以，一个更准确的 v1.4 心智模型是：

```text
                   LangSmith
          Trace / Eval / Monitoring
                    |
                    v
User -> LangChain create_agent / Harness
            |       |       |
          Model   Tools   Middleware
                    |
              MCPAdapter (可选)
                    |
                MCP Server

        create_agent 底层运行在 LangGraph 上
                    |
            State / Persistence
            HITL / Durable Run
```

# 六、建议学习路线

如果你现在从头学 LangChain v1.4，建议按照下面的顺序，而不是一开始就钻 LangGraph：

1. **Model**：`invoke` / `ainvoke` / streaming
2. **Messages**：System / Human / AI / Tool Message
3. **Tools**：`@tool`、schema、`bind_tools`
4. **手写一次 Tool Loop**：彻底理解 Agent 为什么会调用工具
5. **`create_agent`**：把 Tool Loop 交给 Harness
6. **State + Checkpointer**：理解 thread、短期记忆、恢复
7. **Middleware / Structured Output**：理解现代 Agent Harness 的扩展点
8. **LangGraph**：Graph、Node、Edge、State、Interrupt、Persistence
9. **MCP**：用 `MCPAdapter` 把外部 Tool Server 接入 Agent
10. **LangSmith**：Trace、Dataset、Eval、Regression
11. **Deep Agents**：最后再看 batteries-included 的完整 Agent 形态

> 最重要的一条：**先理解 Agent Loop，再学习框架封装。** 这样 LangChain、LangGraph、MCP 换版本时，你依然知道底层到底发生了什么。

# 七、版本更新结论

原资料以 **LangChain v1.3.0** 为基线，主体知识仍然有价值，例如 Model、Tools、`create_agent`、Prompt、Checkpointer、LangSmith 这些核心概念都没有失效。

但用于 2026 年 9 月继续学习时，建议升级到 **LangChain 1.4.x（当前 1.4.2）**，主要需要修正或补充：

- Python 要求从旧资料里的“> 3.8”更新为 **>= 3.10**
- 生态定位更新为 `create_agent` Agent Harness + LangGraph low-level orchestration
- 增加 Middleware / State 的现代 Agent Harness 视角
- 增加 **v1.4 第一方 MCPAdapter**
- 安装命令固定到 1.4.x，避免课程代码与本机包版本漂移

因此，**1.3 不是完全不能学，但已经不是当前最合适的学习基线；现在直接按 1.4.x 学更合理。**
